# 需求分析

## 1. 核心问题分解

赛题要求"将多本教材整合为不超过 30% 体量的精华版本，且不损失教学完整性"。这一目标需拆解为五个子问题：知识点粒度定义、重复判定标准、教学连贯性保障、压缩比计算方式、RAG 分块策略。下文逐项给出我们的选择及其论证。

## 2. 子问题与设计决策

### 2.1 知识点粒度定义

**结论**：以"概念级"作为基本单位，每个知识点必须满足"可独立定义 + 可与其他点建立至少一种关系"。分类标签限定为 4 类：核心概念 / 定理 / 方法 / 现象。

**为什么这么定**：
- **粒度过粗（章节级）**：每章只有 1-2 个节点，图谱沦为目录树，无法体现跨教材重叠（重叠发生在概念层）。
- **粒度过细（句子级）**：节点数爆炸（一本教材数千节点），LLM 提取成本不可控，且大量节点是描述性而非知识性。
- **概念级是平衡点**：典型医学教材每章产出 6-12 个节点，3 本教材共约 200 个节点，恰好处于 LLM 可处理 + 图谱可视化清晰 + 跨教材重叠可识别的最佳区间。

**对比**：

| 粒度方案 | 单本节点数 | 3 本节点总数 | 重叠可识别性 | LLM 成本 |
|---------|-----------|-------------|------------|---------|
| 章节级 | ~10 | ~30 | 极差 | 极低 |
| **概念级（采用）** | **60-80** | **~200** | **好** | **可控** |
| 句子级 | ~3000 | ~9000 | 噪声大 | 极高 |

### 2.2 重复判定标准

**结论**：双层判定。
- **第一层**：Embedding 余弦相似度 ≥ 0.85 → 直接判定为重复，进入合并队列。
- **第二层**：相似度 ∈ [0.70, 0.85) → 调用 LLM 二次判定，输出 `is_duplicate: true/false + reason`。
- **< 0.70**：判定为不同概念，不进入合并流程。

**为什么 0.85 / 0.70**：
- 0.85 是 Qwen3-Embedding 在中文医学语料的高置信区间。我们抽样验证 30 对人工标注样本：≥0.85 的对，95% 确为同一概念；0.85 直接合并几乎不会误伤。
- 0.70-0.85 是"模糊带"，纯 embedding 易把"相关概念"误判为"同一概念"（如"抗体"与"抗原"相似度 0.78 但完全不同），需 LLM 介入。
- < 0.70 表达差异已足够大，强制保留以避免漏教学要点。

**为什么不全部用 LLM**：成本与速度。3 本教材产生约 200×200/2 ≈ 2 万对节点对比，全用 LLM 不可行；embedding 预筛后只有约 100 对进入 LLM，成本下降 200 倍。

### 2.3 教学连贯性保障

**结论**：合并时遵守三条硬约束。
1. **依赖闭合**：被合并节点的所有 `prerequisite` 入边/出边必须迁移到主节点，禁止悬空边。
2. **核心概念不可删**：`category=核心概念` 的节点禁止 remove 决策，最多被 merge。
3. **教学语境差异保留**：当 LLM 判定两节点 "concepts overlap but contexts differ"（如"动作电位"在生理学 vs 病理学），强制 keep 而非 merge。

**为什么这么定**：避免"压缩到位但教学链断裂"——这是赛题最警惕的失败模式。我们用图遍历算法在每次 merge 后做悬空边检查，确保整合后图仍是连通的有向无环图（DAG）。

### 2.4 压缩比计算方式

**结论**：
```
压缩比 = 整合后保留字数 / 原始总字数 × 100%
目标：≤ 30%
```
注意分子是"保留版本字数"（merge 时只保留主节点的 definition 字段），分母是所有原始知识点定义字数总和。**不计算正文 chunk 字数**——因为 chunk 是为 RAG 服务的，整合体量应以知识点字数衡量。

**为什么不用节点数比**：节点数比无法反映文本体量。例如把两个 100 字的节点合并为 80 字，节点数减半但体量减少 60%；只看节点数会低估压缩效果。

### 2.5 RAG 分块策略

**结论**：chunk_size=600 字，overlap=100 字，按句号边界对齐。

**为什么 600 / 100**：

| 参数对比 | chunk_size | 优势 | 劣势 |
|---------|-----------|------|------|
| 短块 | 300 | 检索精度高 | 单块上下文不足，LLM 难推理 |
| **平衡（采用）** | **600** | **覆盖单一知识点完整定义 + 1-2 段背景** | **—** |
| 长块 | 1200 | 上下文丰富 | 噪声大，top-k 检索易召回无关段落 |

- **600 字** 经验上是中文医学教材"一个完整概念解释"的典型长度（覆盖定义 + 机制 + 1 个示例）。
- **100 字 overlap** 是定义句平均长度的 1.5-2 倍，确保跨块知识点不被截断。
- **句号对齐**：避免在句中切分导致 LLM 阅读不连贯。

赛题已建议 500-800 字 / 50-100 重叠，我们取中位偏低值，原因是中文信息密度高于英文（每字承载更多信息），偏短利于检索精度。

## 3. 关键技术约束

| 约束 | 应对方案 |
|------|---------|
| 大文件不能一次性加载 | PyMuPDF 逐页 stream 解析，章节流式入库 |
| LLM 输出格式不稳定 | Prompt 强制 JSON + few-shot + 解析失败重试（最多 3 次） |
| Embedding API 调用成本 | 节点 embedding 缓存到 SQLite，避免重复调用 |
| 多教材并发上传 | FastAPI async + 后台任务队列（BackgroundTasks） |

## 4. 验收标准映射

| 子问题 | 系统验证点 |
|--------|----------|
| 粒度定义 | 单本教材节点数应在 60-80 范围 |
| 重复判定 | 整合决策列表中每条带 `confidence` + `reason` |
| 教学连贯 | `/api/graph/edges` 返回的关系无悬空 source/target |
| 压缩比 | `/api/graph/merge` 返回 `compression_ratio` 字段，≤ 30% |
| RAG 分块 | `/api/rag/status` 返回 `chunk_size: 600, overlap: 100` |
