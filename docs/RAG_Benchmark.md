# RAG Benchmark 自建评测集与实验报告

> 本报告记录我们为 RAG pipeline 自建的评测集设计、实验方法、量化数据与结论。这是 P2 技术报告的核心实验素材。

## 1. 评测集设计

### 1.1 题目分布

共 **20 道题**，覆盖四种类型：

| 类型 | 题目数 | 设计意图 |
|------|--------|---------|
| 事实性（Factual） | 8 | 直接定义、单点查询 |
| 比较性（Comparative） | 4 | 多概念对比，跨章节 |
| 推理性（Reasoning） | 4 | 需要从多 chunk 推理 |
| 跨教材（Cross-textbook） | 4 | 答案需融合 ≥2 本教材 |

### 1.2 题目示例

| 编号 | 类型 | 问题 | 预期引用来源 |
|------|------|------|-------------|
| Q01 | 事实性 | 什么是动作电位？ | 生理学·第二章 |
| Q02 | 事实性 | 炎症的五大临床表现是什么？ | 病理学·第四章 |
| Q05 | 比较性 | 主动运输与被动运输的本质区别？ | 生理学·第二章 |
| Q09 | 推理性 | 为什么 T 细胞在 HIV 感染中会减少？ | 免疫学·第六章 + 病理学 |
| Q14 | 跨教材 | 炎症在生理学与病理学的描述有何差异？ | 生理学+病理学 |
| Q18 | 跨教材 | 免疫应答与超敏反应的关系？ | 免疫学+病理学 |

每道题预先标注 `ground_truth_answer` 与 `ground_truth_citations`（教材+章节）。

### 1.3 评测指标

| 指标 | 定义 |
|------|------|
| **回答准确率** | LLM-as-Judge 与 ground truth 比对，输出 0/0.5/1 |
| **引用准确率** | 召回的 top-5 citations 中正确来源的比例（precision） |
| **引用召回率** | ground truth 引用被命中的比例（recall） |
| **平均响应时间** | 端到端（embedding + 检索 + LLM 生成） |
| **平均 Token 消耗** | 每次问答消耗的 input + output tokens |

## 2. 实验设计

### 2.1 对比变量

我们用同一题集跑了 5 组配置：

| 实验组 | chunk_size | overlap | embedding 模型 | 检索策略 |
|--------|-----------|---------|---------------|---------|
| Exp-A | 300 | 50 | Qwen3-Embedding-8B | 纯向量 top-5 |
| Exp-B | 500 | 80 | Qwen3-Embedding-8B | 纯向量 top-5 |
| **Exp-C** | **600** | **100** | **Qwen3-Embedding-8B** | **纯向量 top-5（线上配置）** |
| Exp-D | 800 | 100 | Qwen3-Embedding-8B | 纯向量 top-5 |
| Exp-E | 600 | 100 | OpenAI ada-002 | 纯向量 top-5 |

### 2.2 实验环境

- 教材：生理学 / 病理学 / 免疫学（3 本，共约 285,000 字）
- LLM：Claude-4.7-opus（gpugeek 接入）
- 评估时间：2026-05-10
- 每题运行 1 次（避免 LLM 随机性影响评分需多次平均，受时间所限暂记 1 次结果）

## 3. 实验结果

### 3.1 chunk_size 对比（Exp-A/B/C/D，固定 Qwen3-Embedding-8B）

| 实验组 | 回答准确率 | 引用 Precision | 引用 Recall | 平均响应时间 | 平均 Token |
|--------|-----------|---------------|-------------|------------|-----------|
| Exp-A (300) | 62% | 58% | 55% | 2.1 s | 1850 |
| Exp-B (500) | 78% | 71% | 70% | 2.4 s | 2400 |
| **Exp-C (600)** | **85%** | **82%** | **78%** | **2.6 s** | **2780** |
| Exp-D (800) | 79% | 73% | 76% | 2.9 s | 3500 |

**结论**：chunk_size=600 在准确率与引用质量上达到最优。300 太短导致定义被截断；800 引入更多噪声召回。600 是中文医学语料的甜点。

### 3.2 Embedding 模型对比（Exp-C vs Exp-E，固定 chunk_size=600）

| 实验组 | 回答准确率 | 引用 Precision | 引用 Recall | 备注 |
|--------|-----------|---------------|-------------|------|
| **Exp-C (Qwen3)** | **85%** | **82%** | **78%** | 中文医学专业术语命中佳 |
| Exp-E (ada-002) | 71% | 65% | 62% | 在"白细胞"vs"白血球"等同义词上召回失败 |

**结论**：Qwen3-Embedding-8B 在中文专业语料上比 ada-002 高出 14 个百分点，主要差距来自专业术语别名识别（如"T 细胞"/"T 淋巴细胞"、"白细胞"/"白血球"）。

### 3.3 题目类型分项准确率（Exp-C 配置）

| 题目类型 | 准确率 | 引用 Precision |
|---------|--------|---------------|
| 事实性 (8 题) | 100% (8/8) | 95% |
| 比较性 (4 题) | 75% (3/4) | 80% |
| 推理性 (4 题) | 75% (3/4) | 78% |
| 跨教材 (4 题) | 75% (3/4) | 70% |

**观察**：
- 事实性题接近满分，pipeline 在直接查询场景表现优异。
- 跨教材题引用 precision 最低（70%），原因是当问题涉及多本教材对同一概念的差异时，top-5 检索容易集中召回单一教材的多个 chunk。
- 推理性题失败案例：Q11"长期高血压如何导致心室肥厚"——需要跨"高血压-心脏后负荷-心室代偿性肥厚"三段推理，单纯 top-5 难以串联完整链路。

## 4. 误差分析

### 4.1 典型失败案例

| 问题 | 失败原因 | 改进方向 |
|------|---------|---------|
| Q11（推理性） | 推理链跨越 3 段，top-5 无法全部命中 | 增加 top-k + cross-encoder rerank |
| Q14（跨教材） | top-5 全部来自同一本教材 | 检索阶段加入 textbook diversity 约束 |
| Q18（跨教材） | "免疫应答"与"超敏反应"语义距离较大但教学相关 | BM25 关键词检索补足 |

### 4.2 改进实验（待完成）

下一步计划：

| 改进 | 预期提升 | 状态 |
|------|---------|------|
| BM25 + 向量混合检索 + RRF | 跨教材题召回 +10% | 已写代码，未跑实验 |
| Cross-Encoder Rerank（top-10 → top-5） | 引用 precision +5% | 待实现 |
| 检索 diversity 约束（每教材 top-2） | 跨教材引用召回 +15% | 待实现 |
| Query Rewriting（LLM 改写问题） | 推理性题准确率 +10% | 待实现 |

## 5. 关键洞察

1. **chunk_size 是 RAG 第一性能杠杆**：从 300 调整到 600，准确率从 62% 提升到 85%，**相当于换一个更强的模型**。
2. **embedding 模型的中文能力差异巨大**：在中文专业语料上，Qwen3 比 ada-002 高 14 个百分点，远超 chunk 调优带来的提升。如果只能改一项，先换 embedding 模型。
3. **跨教材问题需要专门优化**：纯向量检索倾向召回最相似的"局部最优"，需要 BM25 + diversity 约束。
4. **Token 成本与准确率非线性关系**：从 chunk_size 600 → 800，token 上升 26% 但准确率反而下降 6%，更长不等于更好。

## 6. 结论与建议

- **当前线上配置（Exp-C）已是 5 组中最优**：chunk_size=600 / overlap=100 / Qwen3-Embedding-8B / 纯向量 top-5。
- 下一步重点投入：**BM25 + RRF + Rerank**，预期可在跨教材题与推理题上拿到额外 8-12 个百分点提升。
- 长期计划：构建 100+ 题人工标注集，引入自动化 CI 评测，每次代码改动后自动跑 benchmark。
